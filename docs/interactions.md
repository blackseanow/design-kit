来自原项目 `docs/ui-consistency/component-interactions.md` 的通用部分，按 kit 的实现整理。“已测”表示 `tests/browser_check.js` 在 Chromium 里自动检查过。

| 组件 | 打开和反馈 | 关闭、取消和焦点 | 已测 |
| --- | --- | --- | --- |
| 侧栏导航 | 当前页：品牌色文字 + 淡品牌底，`aria-current="page"` | 点击导航直接跳转 | 否 |
| 选项卡 | 品牌色文字 + 底部 2px 线 | 左右方向键、Home、End 切换；窄屏只让选项卡区域横向滚动 | 是 |
| 下拉 | 和输入框同宽；选中项有勾和淡品牌底；手机上每项至少 44px | ↑↓ Home End 移动；Esc 只关闭菜单并把焦点还给按钮；Tab 关闭后继续往下；选择后原 `<select>` 触发 `change` | 是 |
| 可搜索下拉 | 输入即过滤；无结果显示“没有匹配结果”；禁用项不可选 | 点击外部或 Esc 关闭；触屏设备不自动聚焦搜索框（避免弹出键盘） | 是 |

| 弹窗里的菜单 | 下拉、日期菜单挂到弹窗内部，不被正文滚动裁切 | 第一次 Esc 只关菜单，第二次才关弹窗 | 是 |

| 手机侧栏 | 从左侧滑入（350ms），背景模糊遮罩，页面不能滚动 | 菜单按钮、遮罩、Esc、点击导航都会关闭；关闭后焦点回到菜单按钮；打开时 Tab 只在菜单按钮和侧栏之间循环 | 是（Esc） |
| 用户菜单 | 点击头像展开 | ↓ 打开并聚焦第一项；↑↓ Home End 移动；Esc 关闭并回到触发按钮；点击外部关闭 | 否 |
| 行操作 | “更多操作”按钮展开菜单 | ↓ 打开并聚焦第一项；Esc 和 Tab 关闭；点击菜单项后关闭 | 是（Esc） |
| 帮助图标 | 鼠标悬停或键盘聚焦时显示；点击后固定，并出现关闭按钮 | Esc 关闭；锚点滚出可视区或被弹窗头尾遮住时自动隐藏 | 是（聚焦、Esc） |
| 全局提示 | 成功 3.2 秒、警告 6 秒、错误 7 秒后自动消失；信息和处理中不自动消失 | 鼠标悬停或焦点在提示里时暂停计时；Esc 关闭；焦点回到原来的位置 | 部分（显示） |
| 按钮加载 | 禁用、转圈、显示“保存中”等文字 | 结束后恢复原来的内容和可用状态 | 是 |
| 顶部进度条 | 2px，点击站内链接或提交表单时开始 | 页面加载完成后走满再淡出；未完成时不显示 100% | 是（结束） |
| 密码显隐 | 默认辅助文字色；显示密码后品牌色 | 只切换输入框类型、`aria-pressed` 和按钮名称，焦点留在按钮上 | 否 |

## 通用约定

- 所有浮层都有可见的 `:focus-visible` 样式，不能只靠颜色表示选中，选项卡用底线，下拉用勾。
- 浮层不用 `title` 属性代替说明文字，帮助文字放在 `data-help`。
- 不使用浏览器原生 `alert` / `confirm`。
- 请求失败时显示原因和重试，不显示假的成功结果。
- 不确定是否已执行的操作（例如网络中断）不要自动重试提交。
